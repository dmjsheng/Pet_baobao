# 爆爆第三版逐帧动画设计

## 目标

把第二版的 CSS 位移/缩放效果升级为逐帧播放的桌面宠物动画。视觉继续使用现有暖色 Q 版、蓝眼暹罗猫爆爆主形象；不重做写实形象，不新增声音、联网或系统通知。

## 动作范围

第三版只制作四组动作，每组保持透明背景、统一画布尺寸与相同的爆爆外观。

| 动作 ID | 帧数 | 播放方式 | 画面内容 |
| --- | ---: | --- | --- |
| `idle-look` | 6 | 无限循环 | 看着用户、眨眼、耳尖与尾巴轻动 |
| `pet-nuzzle` | 6 | 单次播放 | 探头、闭眼、蹭蹭、回到站姿 |
| `eat-treat` | 8 | 单次播放 | 看零食、伸爪、低头吃、满足眯眼 |
| `yarn-chase` | 8 | 单次播放 | 注意毛线球、起跑、追逐、小扑跃、回头 |

四组共 28 帧。帧图通过图像生成按“同一角色的多格动作序列”产出，而不是手工逐像素绘制；再用确定性的本地裁切脚本拆成单帧 PNG。

## 资源规范

- 输入参考：`assets/baobao/baobao.png`，即第二版爆爆主视觉。
- 输出目录：`assets/baobao/frames/<动作 ID>/000.png` 至对应末帧。
- 每帧 PNG 必须是透明背景、同一宽高、完整猫身可见、底部对齐。
- 动作序列图仅包含爆爆和必要的小道具：`eat-treat` 允许零食，`yarn-chase` 允许毛线球；不出现房间背景、文字、水印或边框。
- 允许因生成结果不稳定重做某一整组序列；不把不同生成批次的帧混在同一动作中。

## 播放模型

新增独立 `frame-animation` 模块，输入动作 ID 与当前时间，输出当前帧索引。它不依赖 DOM，便于测试循环、单次播放结束和帧间隔。

- 默认状态使用 `idle-look`，每帧约 170 ms，循环播放。
- 抚摸触发 `pet-nuzzle`，每帧约 115 ms，播放结束回到 `idle-look`。
- 喂食触发 `eat-treat`，每帧约 150 ms；保留第二版爱心效果，但主猫不再用缩放跳跃替代动画。
- 毛线球触发 `yarn-chase`，每帧约 110 ms；保留毛线球短暂覆盖层，主猫按帧追逐与扑跃。
- 睡眠、陪伴和低频自主动作暂时继续沿用第二版现有 CSS 动画；本期不扩大帧图数量。
- 任意新的用户动作会中断上一个一次性序列并立即开始自身序列；播放完成后回到 `idle-look`。

## 应用接入

渲染器把当前帧文件设置为现有宠物 `<img>` 的来源。静态资源复制脚本会把 `assets/baobao/frames` 一并带入开发构建和便携版；主进程仍只给渲染器提供本地资源 URL，不改变权限边界。

为避免频繁的文件系统 IPC，启动时渲染器根据资源根目录构造帧 URL；帧的切换只发生在浏览器内。所有动画保持静音、可拖动、始终置顶，帧图和覆盖层不拦截鼠标。

## 测试与验收

- 单元测试：循环动作的帧索引回绕；单次动作在末帧停止；中断后从新动作第 0 帧开始；四组配置的帧数与帧间隔正确。
- 资源测试：四个动作目录均含连续编号的 PNG，数量分别为 6、6、8、8；所有帧尺寸一致。
- 打包测试：便携版包含四组帧资源；浏览器打包文件不含 `require()`。
- Windows 手工验收：待机眨眼不抖动；点击有完整蹭蹭；喂食完整吃完再出现爱心；毛线球完整追逐再回看；连续操作能立即切换；全程无声音。

## 范围边界

本期不制作完整 11 行精灵图、16 朝向、行走路径、视频/GIF 文件、音效或额外互动动作。若生成序列无法保持爆爆外观稳定，则停止接入该序列，先请用户确认替代帧图，而不以低质量资源覆盖当前应用。
